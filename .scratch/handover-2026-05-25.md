# Bugs Fixed

- Maven was initially unavailable; Maven wrapper was added and tests can now run with `./mvnw test`.
- H2 rejected multi-column `ALTER TABLE ... ADD COLUMN` syntax in PostgreSQL mode; migration V3 uses separate `ALTER TABLE` statements.
- Generic `Map.of(...)` exception responses were replaced with `ApiErrorResponse` so clients receive stable `code`, `message`, `path`, `requestId`, and validation `fieldErrors`.

# Key Decisions & Why

- Trips do not store single-principal fields. Multiple principals are modeled through `trip_principals` because a family, delegation, or executive party can arrive on one trip.
- Concierges do not have user accounts. They should use trip-scoped capability access so field operations stay lightweight and revocable.
- WhatsApp is a channel, not the source of truth. ArrivalOS records timeline events first, then sends Kapso messages.
- Refresh tokens are JWTs but still stored by hash server-side. This keeps JWT portability while preserving revocation and rotation.
- Email verification and password reset tokens are opaque externally and stored only as hashes.
- API error codes currently derive from `ResponseStatusException` messages, but the next hardening step should introduce explicit domain exception codes.

# Lessons Learned & Gotchas

- Keep Flyway migrations compatible with both PostgreSQL and H2 test mode.
- Avoid storing raw tokens anywhere.
- Do not add concierge login routes unless product strategy changes.
- Do not let frontend-visible error codes depend on human copy long-term.
- Use tests to protect security flows because token lifecycle regressions are easy to miss manually.
